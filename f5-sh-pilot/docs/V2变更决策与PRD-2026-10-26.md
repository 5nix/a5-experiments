# A5 SH实验V2变更决策文档兼PRD

Oct 26, 2026 · @AsakawaNana

新版把消息时机扩展为T0（即时）、T1（系统中断点）、T2（人主体中断点）三种，新增SH06、SH07两组任务，取消组间休息，改为在每组任务的第二单元（U2）中安排一次被试自主发起的30秒休息，T2消息在休息开始后5秒送达。本文以现有程序为起点，列出全部需要的修改；与仓库中PRD.md、DECISIONS.md、CONFIG.md冲突时，以本文为准。技术实现由开发agent决定。

标注说明：【已定】为团队已确认的决定；【默认】为可以先按此实现、实验负责人可调整的设定；【待定】为尚未决定的事项，不阻塞开发。

## 1. 术语与研究逻辑

研究的核心问题是：与即时出现相比，机会性出现的消息是否更好、好在哪里；以及"系统中断点"和"人主体中断点"是否本质不同。

| 代号 | 名称 | 定义 | 本实验中的触发点 |
| --- | --- | --- | --- |
| T0 | 即时出现 | 消息一到达就呈现，现有产品九成以上采用这种方式 | U1补充资料首次实际呈现（E） |
| T1 | 系统中断点 | 中断的主体是任务，系统日志可以查到（提交、停止操作等）；此时人可能仍在思考 | U2首次实际呈现（即U1提交后） |
| T2 | 人主体中断点 | 中断由人自己发出，依据人的行为、注视、环境状态判断；真实产品中需要多传感器 | U2中被试自主开始休息后5秒 |

- 【已定】旧命名T1.1、T1.2分别改为T1、T2；程序和配置里原来的T1即新T1，含义不变。
- 【已定】统一用"消息到达、推迟送达"来理解三种时机：消息都在E时刻到达；T0到达即送达，T1推迟到下一个日志可查的任务断点，T2推迟到被试发出的中断。
- 【已定】本研究不做检测算法，采用Wizard of Oz思路：T2由被试点击休息来发起，论文中要说明，这个点击是传感器检测的替代，代表人发出的中断，而不是任务事件。
- 【已定】为了能比较两种中断的本质差异，T2的时刻不能由任务脚本决定，也应尽量避免与任务边界重合（理由与相关文献见第11节）。
- 【已定】延时类时机（如"稍后提醒"）和勿扰模式不纳入本次研究。

## 4. 正式流程

【已定】新版流程为：操作教程 → 情景导入 → 7组任务 → 完成页。每组任务内的步骤如下：

1. 说明卡。
2. U1：被试展开补充资料，首次实际呈现记为E。T0组在E时送达消息。
3. 提交U1后直接进入U2，不加中间页、延时或按钮（与现有程序一致）。T1组在U2首次实际呈现时送达消息。
4. U2中，被试在自己觉得合适的时候休息一次（30秒）。所有条件（包括NONE）都有这次休息；T2组在休息开始后5秒送达消息。规则见第5、6节。
5. 提交U2。
6. 消息理解题：先答"是否注意到消息"，再答内容题。NONE组以及T2未触发的组跳过。
7. 信息体验评价量表5题：第6步选"没有注意到任何消息提示"时跳过；NONE组跳过。
8. 直接进入下一组的说明卡，【已定】取消组间休息。第7组结束后进入完成页。

【默认】操作教程增加休息功能的说明：介绍休息按钮和提示语（见第5节），并让被试试点一次。练习时的休息可以缩短，教程数据照常标记为tutorial，不计入正式数据。

其他现有规则保持不变：主任务、理解题和评价全部必答；U1提交前必须实际显示过补充资料；不向被试提示正误；情境时钟随任务更新；每组最多一条正式消息；刷新、恢复、重连不重发。

## 5. U2自主休息

【已定】每组任务的U2中，被试可以自主发起一次30秒休息，所有条件一致。这样做是为了让休息本身的效果在各条件间抵消，只有送达时刻不同；U1用来积累负荷，使休息成为从忙碌到静止的转变。

**规则**

- 【已定】只在U2中提供，U1不提供。每组只能休息一次。
- 【已定】休息按钮在U2中始终显示，外观始终不变，不能让被试看出"解锁"时刻，否则按钮变化本身会变成休息提示。
- 【已定】设一个看不出来的时间窗口下限：U2出现后的前X秒内点击，不开始休息，只显示文字"请先做一部分再休息"。目的是避免被试一进入U2就休息，使T2和T1撞在一起。
- 【已定】X可配置，用第一次pilot数据计算：取"U2出现到第一次填写答案"时间分布的第75百分位左右。各组可以共用一个值，也可以按组设置。
- 【已定】提示语：“第二单元做题过程中，在你觉得需要的时候休息一次，不要刚开始就休息，也不要在准备提交时休息。”【默认】在操作教程中说明；正式任务中按钮旁不加常驻文字，避免持续提示。
- 【已定】程序不主动提醒休息，因为程序提醒会制造休息时刻。被试一直未休息时，由主试决定是否通过后台按钮提醒（第7节）。
- 【已定】不强制休息：未休息也可以正常提交U2。

**休息期间**

- 【默认】显示休息页并遮挡任务内容，避免边休息边看题；30秒后自动回到U2，已填答案和草稿保留；不提供提前结束。
- 【待定】休息页是否显示倒计时。显示会让被试在接近结束时提前准备回到任务；定下来之前默认显示。
- 【默认】主试人工暂停时，休息计时冻结，与现有休息计时规则一致。
- 休息期间眼镜消息照常显示；持续确认模式下，被试可以在休息中确认。

## 6. 消息触发与送达

【已定】T0、T1触发规则不变，新增T2：在休息开始后5秒送达。

| 条件 | 触发事件 | 未发生时 |
| --- | --- | --- |
| T0 | U1补充资料首次实际呈现（E） | 不补发（现有规则，U1提交前必须显示过资料） |
| T1 | U2首次实际呈现 | — |
| T2 | U2中休息开始后5秒 | 提交U2前未休息：不送达，记为"T2未触发" |

- 【已定】延迟5秒的理由：刚点休息的头两三秒，被试还在调整姿势、可能仍在想题；5秒延迟加11秒显示，消息在第16秒左右消失，30秒休息还剩约14秒供被试消化；也贴近真实传感器判断"静下来"所需的时间。延迟值可配置。
- 【默认】休息开始时刻以休息页实际可见为准，与程序现有的"实际呈现"原则一致。
- 【已定】T2未触发时不能在提交时补发，那样会变成系统断点，污染T2。这一组跳过理解题和量表，按缺失数据处理。
- 【已定】主试提醒后才开始的休息，T2照常送达，但标记为"提醒后"。
- 【默认】被试点击休息时不因眼镜状态而拒绝，休息照常开始。如果第5秒时眼镜未就绪或正在显示，按现有规则：不覆盖、不排队、不补发，记录失败原因。
- 现有规则继续适用：每组最多一条正式消息；刷新、恢复、重连不重发（包括休息中刷新）；显示时长与呈现模式沿用现有配置；发送意图、设备回执和实际显示时间分别记录，未知时间留空。

## 7. 主试后台

【已定】后台增加"提醒休息"按钮：主试点一次，系统同时完成提醒和记录，一举两得。

- 【已定】只在被试处于U2且本组尚未休息时可用；是否使用完全由主试判断，程序不自动触发。
- 【已定】点击后在被试电脑屏幕上显示一句固定提醒语，并记录提醒时间；之后发生的休息自动标为"提醒后"。比起口头提醒，措辞每次一致，时间也记得准。
- 【默认】提醒语为“别忘了在本单元中休息一次。”以不遮挡任务的轻量方式显示几秒后自动消失；不在眼镜上显示，避免与实验消息混淆。
- 【默认】如果主试仍然口头提醒了，应在备注中记录，分析时同样视为"提醒后"。
- 【默认】后台会话详情中显示本组休息状态：未到窗口 / 可休息 / 休息中 / 已休息 / 未休息即提交，以及U2已进行的时间、是否已提醒、T2消息状态，方便主试判断是否需要提醒。
- 主试和后台屏幕应在被试视线之外，避免被试从主试的动作中猜出什么。

1. SH06 U2题干漏了一项：题干只说"重新计算设备操作说明的用纸数，以及合计"，答题区却要求填讲解资料。建议改为"重新计算设备操作说明和讲解资料的用纸张数，以及三种资料的合计用纸张数"。

3. A07对应的事项与其他组不一致：其他组的A消息都对应说明卡里的待办事项，A07却是"制作签到表"，而说明卡的待办是"发送到场通知"。理解题干扰项B正好是"各组人员到场通知"，被试可能凭说明卡的印象误选。
4. SH06、SH07都是纯计算题，负荷可能低于SH04等排班推理题。拉丁方能平衡这种差异，但会增加误差。

## 11. 不做的事

以下方案在讨论中已经排除，开发和后续修改不要重新引入。

| 不做 | 理由 |
| --- | --- |
| 在U1和U2之间加过渡页或中间环节 | T1代表"系统检测到任务断点就推送"，真实系统中提交后马上出现下一屏，人往往还在想任务，这是T1的本质特征。加间隙会人为改变T1 |
| 把T2的诱发放在任务边界（如U1提交处） | 人的状态转变会和任务边界绑在一起，无法区分效果来自人的状态还是任务边界，取消了研究要比较的东西 |
| 只在T2组提供休息 | 休息本身的恢复效果会混入T2；被试会把"能休息的那组"当成线索；疲劳分布不均 |
| 程序主动提醒休息 | 程序提醒会制造休息时刻，休息就不再是被试自己发起的 |
| 休息按钮可见地定时解锁 | 按钮亮起本身就是提示，休息时刻实际上由系统决定，T2会退回系统时机 |
| T2未触发时在提交时补发 | 提交是系统断点，补发会污染T2 |
| 由主试叫被试起身、敲门等外部事件来诱发 | 这些动作本身就是一次打断 |
| 做中断点检测算法或传感器检测 | 本研究只提供设计建议，采用Wizard of Oz思路 |
| 延时类时机（稍后提醒）、勿扰模式 | 不在本次研究范围内 |
| 恢复组间休息 | 已由U2内自主休息替代 |

依据：[Katidioti & Taatgen (2014)](https://www.ai.rug.nl/~niels/publications/Human%20Factors_%20The%20Journal%20of%20the%20Human%20Factors%20and%20Ergonomics%20Society-2014-Katidioti-728-36.pdf)发现，系统空闲时人仍保持工作记忆，此时切走代价最高，对应"任务中断但人还在思考"；[Salvucci & Bogunovich (2010)](https://researchdiscovery.drexel.edu/esploro/outputs/conferenceProceeding/Multitasking-and-Monotasking-The-Effects-of/991019170480804721)发现，可以自己选择时，约94%的切换发生在低负荷时段，说明用户自己选的时刻能反映人主体断点；[Ho & Intille (2005)](https://www.media.mit.edu/publications/using-context-aware-computing-to-reduce-the-perceived-burden-of-interruptions-from-mobile-devices)发现，在活动转换时送达的消息比随机送达更受接受。

## 13. 分析要点

本节写给研究者，说明上述设计对分析的要求，也是第10节要记录这些数据的原因。

- 把"是否注意到消息"作为主要结果之一。它直接回答"信息是否被有效获取"，各条件的注意率可以直接比较。
- 量表只在注意到消息的人里分析，每个条件报告实际样本量。T0的消息出现在高负荷时刻，没注意到的人可能更多，剩下的评价者可能偏好；论文中需说明这是"在注意到消息的前提下"的比较。
- 打扰感4题要在本研究数据上计算信度（如Cronbach's α），因为原量表是在广告情境下验证的。
- 把理解题第1题的自我报告和"已阅读"按键记录对照，检查两者是否一致。
- T2的消息在休息时出现，当时没有主任务在进行，打扰感几乎必然对T2有利。主观评价只是一部分证据，更有说服力的是主任务表现、恢复作答时间、理解题成绩和注意时间。
- "消息显示到理解题出现的间隔"作为协变量，因为T0的消息离理解题最远，理解题差异可能部分来自记忆衰退。
- 敏感性分析：排除"提醒后"的休息、排除离任务边界很近的休息后，结果是否不变。
- 报告T2未触发比例和发送失败比例，两者分开报告。
- 每组都有被试自主休息的时间点，可以分析T0、T1的消息相对这个时间点落在哪里，以及被试自己选择的休息时刻是否倾向于任务边界。若大多数都落在边界上，说明在这类任务里T1是T2的一个不错的近似，这本身也是结论。
