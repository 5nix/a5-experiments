# 界面与交互维护

public/experiment.*和desktop.css组成被试端，admin.*和app.css组成主试后台。均为原生ES module，无构建步骤，遵守本站脚本与样式CSP；题目和流程由服务端view驱动。

## 被试工作台

整个流程使用工作台窗口；附件和草稿本是独立子窗口，可最小化、最大化、关闭，工作台不可关闭。窗口自动排列，不提供拖动缩放。桌面宽度至少1180px时采用附件、工作台、草稿本三栏；较窄时子窗口浮在工作台上方。

任务页为文档、填写区和底部下一步。宽度不足时上下排列；表格以原生文本显示，附件以.xlsx/.docx文件磁贴打开。数值和时间每行一项，较多选项使用空白下拉框，其他选择题使用按钮组；缺失字段和未查看附件会有明确提示。

草稿本按单元保存，教程使用独立草稿。右下角情境时钟从教程首屏显示，随任务情境更新，组内不走动；切换新设定时间时短暂闪烁，刷新同一时间不重复闪烁。000在任务栏有跳转入口，含适用教程页；正式被试无自行跳转入口。

含确认模式的页面在任务组进度后、草稿本前放“已阅读通知”，使用相同按钮样式和黑色铃铛SVG。无待确认消息时可点击但不发送确认；有消息时按request_id确认，跨页不丢失，必要时读取最新状态避免轮询延迟。没有底部确认弹窗。手动确认型通知也可使当前页出现此按钮。

教程复用任务框架；确认模式先学习工具，再阅读练习通知、完成须答对的理解题，其他模式只有工具页。教程不展示正式刺激内容，具体规则见 [DECISIONS.md](DECISIONS.md)。

## 可见证据与保存

- 工作台置顶、文档可见且完成两帧绘制后报告displayed；generation防止旧页回调误报。
- 附件查看器实际可见、未最小化并完成两帧后报告reveal_displayed。关闭不清除既有E证据，切页关闭查看器，刷新按保存状态恢复。
- 答案和提交走串行队列；草稿本约450ms延迟保存，提交、切页、关闭或隐藏前主动保存，卸载使用keepalive并保留原page_token。
- 轮询只在phase或page_token变化时整体渲染，消息确认状态单独更新，避免打断输入法与焦点。

## 主试后台

| 区域 | 当前交互 |
| --- | --- |
| 标题栏 | 设备状态；“主试二维码”位于两页切换器左侧，默认折叠 |
| 会话列表 | 配置文件、被试、新建；进行中/已结束分组、全部导出及可恢复删除 |
| 实时状态 | 任务进度、本组消息的请求/绘制证据及异常 |
| 实验干预 | 跳转在可选原因上方；暂停/停止并排，删除二次确认 |
| 入口与备注 | 被试链接、二维码、连接状态、恢复入口、访谈备注和单次导出 |
| 准备与检查 | 设备控制、三种模态手动通知、材料检查、配置下载与导入 |

新建成功后不把当前会话提示成重复创建错误；真正重复请求仍由服务端拒绝。主试控制与数据权限以服务端available_actions为准。配置文件操作见 [CONFIG.md](CONFIG.md)。

手机采用列表/详情单列切换。设备表单和历史使用独立DOM，轮询不覆盖正文；通知请求保留固定ID用于幂等重试。无会话通知独立记录，进行中手动通知关联会话并标记manual。scrcpy打开独立左眼监看窗口，恢复连接不补发消息。

被试入口由服务器保存，浏览器sessionStorage仅缓存；后台无管理员key。恢复入口会使旧token失效。二维码在本机生成；在手机访问前仍需验证网卡可达性与防火墙。
